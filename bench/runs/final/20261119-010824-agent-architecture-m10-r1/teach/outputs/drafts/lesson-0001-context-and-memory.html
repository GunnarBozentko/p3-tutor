Context and memory in an agent

By the end of this lesson you can say what your makerspace assistant sees at each step, what it keeps between sessions, and how it finds one page in a long manual.

Warm-up 1 min

Recall

In the agent loop, the model asks for a tool. Who actually runs the tool, and where does the result go next?

Check your answer

The program around the model runs the tool and adds the result to what the model sees on its next call. Today's question is what that "what the model sees" holds.

The context window 2 min

Example: a student asks, "Can I use the laser cutter on Friday?" Call 1 sends the instructions and that question. The model asks for the calendar, and call 2 sends the instructions, the question and the calendar result. The model never keeps call 1; the program re-sends it.

In general, a model keeps nothing between calls except what you send it again. It sees only the context, which Anthropic defines as the set of tokens (small pieces of text) included when sampling from the model (Anthropic). The context window is the maximum size of that set.

In an agent, the program rebuilds the context before every model call. It holds the prompt (the standing instructions), the tool descriptions (the names and usage rules that tell the model which tools exist), the conversation so far, and every tool call and result since the run began. Each step adds to it, and nothing leaves unless the program removes it.

Think of a soccer analyst who forgets everything between questions. Before each question, the staff (the program) hands over a folder: the game plan, every earlier question, every report pulled so far, and the new question. The analyst (the model) reads the whole folder each time. A thicker folder takes longer to read, and the key page gets buried.

A common mix-up

It is tempting to think the model remembers earlier steps the way a person does. It does not: it re-reads them. If the program drops a tool result from the context, the model has no trace of it.

Your turn

Suppose a window holds 8,000 tokens (an illustrative size). The prompt and question take 2,100 tokens, and each tool round (one tool request plus its result) adds 900. On which model call does the context first fail to fit?

Show a solution

Call k sends 2,100 + 900 × (k − 1) tokens. Call 7 sends 7,500, which fits. Call 8 sends 8,400, which does not. The program must remove old tool results before call 8 (techniques named below).

A bigger window is not a fix. Anthropic reports context rot: as the token count grows, the model recalls details from the context less accurately (Anthropic). The goal is the smallest set of tokens that still holds what the next step needs.

What a long run costs 2 min

You pay for the tokens sent in each call, so re-sending the context makes cost grow faster than the step count. Cost per request is your sponsor's constraint.

Everyday version: you phone a help line whose agent forgets every call. You must read out your whole case history each time, and the line bills per minute. Each new call has a longer history to read, so the bill grows faster than the number of calls.

Worked example

The prompt, tool descriptions and question take 2,100 tokens. Each tool round (the request plus its result) adds 900 tokens. The assistant makes four model calls. How many input tokens (the tokens sent to the model, not those it writes) are sent in total?

  1. Call 1 sends 2,100 tokens.
  2. Call 2 sends 2,100 + 900 = 3,000, because one round was added.
  3. Call 3 sends 3,000 + 900 = 3,900, and call 4 sends 3,900 + 900 = 4,800.
  4. Total: 2,100 + 3,000 + 3,900 + 4,800 = 13,800 tokens, not 4 × 2,100 = 8,400.
Your turn

The prompt and question take 1,500 tokens, and each tool round adds 600. The assistant makes three model calls. Call 1 sends 1,500 tokens. Call 2 sends ___, call 3 sends ___, and the total is ___.

Show a solution

Call 2 sends 1,500 + 600 = 2,100. Call 3 sends 2,100 + 600 = 2,700. Total: 1,500 + 2,100 + 2,700 = 6,300 tokens.

General form: let p be the starting tokens and r the tokens added per round. Call k sends p + r(k − 1). Summing over n calls gives n·p + r(0 + 1 + … + (n − 1)) = n·p + r·n(n − 1)/2. Check: 4 × 2,100 + 900 × 6 = 13,800. The total grows roughly with n².

Two tools keep this in check. Context editing clears stale tool calls and results from the context when it nears the limit (Anthropic). Compaction summarizes a conversation nearing the limit and starts a fresh context from the summary (Anthropic).

Between sessions: notes 2 min

When a session ends, the context is gone. Anything the assistant should know next visit must be saved outside the context, then loaded again. This is structured note-taking: the agent writes notes to storage outside the window and pulls them back later (Anthropic). The notes file is the scouting database that stays in the club office between matches; before each match, staff copy the relevant pages into the analyst's folder.

The program owns that storage, like the JSON files you already read in Python. Anthropic's memory tool is one version of it: Claude stores and consults information outside the context window through files, and the developer controls where they are kept (Anthropic).

import json, os

def _read():
    if not os.path.exists("notes.json"):
        return {}
    with open("notes.json") as f:
        return json.load(f)

def save_note(student_id, note):
    notes = _read()
    notes.setdefault(student_id, []).append(note)
    with open("notes.json", "w") as f:
        json.dump(notes, f)

def load_notes(student_id):
    return _read().get(student_id, [])

At the start of a session, the program calls load_notes and puts the result in the context. A note such as "prefers mornings" is then available without the student repeating it.

Safety: a note is not a permission

Do not save "trained on the laser cutter" as a note and trust it later. A note is a copy that can go stale. The assistant must call a tool that reads the makerspace's training record at the moment of the booking. If that tool fails, the answer is "not permitted yet", with a pointer to staff who can confirm. A note may only remind the assistant to check.

Check yourself

A student says, "Last week you told me I could use the 3D printer." The assistant has no saved note about it. What should the assistant do?

Show the answer

Call the training-record tool. Neither the student's claim nor the absence of a note decides the booking.

Retrieval from long manuals 2 min

Retrieval means fetching only the pieces of a large source that the current question needs, then placing them in the context. A 300-page manual does not belong in the context: it would cost tokens at every call and invite context rot.

Anthropic describes two timings (Anthropic). Upfront retrieval fetches relevant data before the model runs. Just-in-time retrieval keeps lightweight references, such as file paths or queries, and lets the model load data through tools when needed. Just-in-time runtime exploration is slower than retrieving pre-computed data.

ChoiceExample for the assistant
Always in contextRules, tool descriptions, the student's saved notes
Retrieved on demandThe two manual pages about laser cutter settings, via a search tool
Read from a recordTraining status and calendar, via a tool each time

Illustration with made-up sizes: if a 300-page manual is about 150,000 tokens and a search tool returns 2 pages of about 1,000 tokens, each call carries 1,000 tokens of manual instead of 150,000, which is 150 times fewer. Notes and retrieval together are the assistant's long-term memory: both live outside the window and enter it only when the program loads or retrieves them.

Statistics view: retrieval is sampling. The manual is the population, the query is the selection rule, and the 2 returned pages are the sample. The selection is targeted, so it can be biased: if the search misses the page with the warning, the answer is wrong however carefully the model reads.

A tool result is also context. A search tool that returns three pages costs far less than one that returns thirty, so return few, relevant, short results.

Check yourself

The assistant answers a question about a drill press from a 300-page manual. Which design keeps cost lowest per request?

Show the answer

The search tool. Only the pages the question needs enter the context.

Summary 1 min

  • The model sees only the context, which the program rebuilds and re-sends at every call; a run's context grows with each step.
  • Re-sending makes cost grow faster than the step count, and a long context recalls details worse.
  • Between sessions, only what the program saved in storage survives; notes are loaded back into the context.
  • Retrieval brings in only the needed pages; safety facts come from a record read by a tool, never a note.
