Context and memory in an agent

One-page reference from the lesson Context and memory in an agent.

Where a fact lives

QuestionPlace
Needed on every call, short, same for everyoneFixed part of the window (system prompt)
Durable about one student, harmless if staleNotes, loaded at session start
Large, shared, stable (manuals)Library, searched on demand (retrieval)
Owned by a system of record or changing by the minute (training status, calendar)Read by a tool on this request; never from a note or a claim

Token arithmetic

  • Tokens: about words / 0.75 (rule of thumb); count exactly with the provider's counting tool.
  • Input at call k = fixed part + everything added so far (requests, results, question).
  • Total input over n calls = nF + d × n(n − 1) / 2 for F fixed tokens and d added per step.
  • Cost = tokens × price per million / 1,000,000. Output is billed too.

Keeping the window small

  • Clear finished tool results (lightest).
  • Compaction: summarize and restart; pays off when saving per call × calls exceeds the summarizing read.
  • Helper agent: keeps the main window small; the helper's read is still billed.

Retrieval

  • Chunk the manual; keyword search (BM25, rare words weigh more) finds exact codes; embeddings find paraphrases.
  • Cosine similarity = (q · x) / (|q| |x|); keep the top k chunks.
  • Measure misses: recall at k on a labelled set of real questions.
