Context and memory in an agent

From lesson 1.

Where information lives

PlaceLastsUse for
Context (the messages sent each call)One call or runInstructions, tools, current request, needed results
Notes (saved by the program)Across sessionsPer-student facts
Retrieval indexAs long as the documentsLarge static text such as manuals
Live tool callNot storedFast-changing data such as the calendar

Formulas

Total input tokens  T = n*C0 + d*n*(n-1)/2
  n  = model calls, C0 = starting context, d = tokens added per step
Rough tokens        len(text) // 4
Recall at k         questions whose right chunk is in the top k / all test questions

Rules

  • The model keeps nothing between calls; the program's messages list is the memory.
  • Every token in the context is billed on every call, and recall may weaken as it grows (context rot).
  • Manage size by trimming used tool results, compaction, or sub-agents.
  • Save facts that must survive exactly in notes, not only in a summary.
  • Hybrid retrieval (embeddings plus BM25) misses less than either alone; test on real questions.

Sources: Anthropic, Effective context engineering; Anthropic, Contextual Retrieval.
