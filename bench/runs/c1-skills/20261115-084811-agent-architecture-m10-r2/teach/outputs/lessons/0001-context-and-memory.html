Context and memory in an agent

By the end of this lesson you can say what the assistant sees at each step, what survives between steps and between sessions, and choose retrieval or notes for a given piece of information.

Why this matters for you

The makerspace assistant must answer from long machine manuals and remember each student's training status between visits. Both are context and memory decisions, and each one changes your cost per request.

The program runs the tool and appends the result to the conversation, then calls the model again. That growing conversation is today's topic.

1. The context window 3 min

The context window is the maximum amount of text, counted in tokens, that the model can look at in one call. A token is a chunk of text, roughly a short word or word piece; usage is billed per token. The window holds everything: the instructions, the tool descriptions, the conversation so far, tool results and the model's own output (Anthropic docs: context windows).

The model has no memory of its own between calls. At every step of the loop, the program builds the full input again: instructions, tool descriptions, the question, and every earlier tool request and result. Think of a soccer commentator who is handed the full match transcript before every sentence: nothing is remembered, everything is re-read.

Two consequences. First, the window is a hard limit: if a manual does not fit, it cannot be read in whole. Second, a bigger window is not free: Anthropic describes context rot, where recall accuracy falls as the window fills, and advises keeping the smallest set of high-signal tokens (Effective context engineering for AI agents).

Worked example: input tokens over a request

Instructions plus tool descriptions take 2,000 tokens. Each step adds 1,000 tokens (request plus result). The input of call k is 2,000 + 1,000(k − 1). For n = 5 calls:

  1. Per-call inputs: 2,000; 3,000; 4,000; 5,000; 6,000.
  2. Sum: 5 × 2,000 + 1,000 × (0+1+2+3+4) = 10,000 + 10,000 = 20,000 input tokens.
  3. General form: 2,000n + 1,000 · n(n−1)/2. The second term is quadratic in n, so long loops get expensive quickly.

2. What is kept, and for how long 2 min

Memory in an agent is therefore a program design choice, not a model property. Lilian Weng's overview calls the context window the agent's short-term memory and external storage the long-term memory (LLM Powered Autonomous Agents).

A common mix-up

"The model remembers the student from last week." It does not. Unless your program saved something and put it back into the next session's context, the model starts blank. A chatbot that seems to remember is doing exactly that behind the scenes.

Check yourself

A student chats for ten minutes, closes the page, and returns tomorrow. What can the assistant use from yesterday?

Show the answer

Only what the program saved and loads back in.

3. Retrieval and notes 3 min

Retrieval means searching a large store of text outside the window and putting only the best-matching pieces into it. A manual of 300 pages stays in a file; for a question about the laser cutter's focus, the program fetches the two relevant paragraphs. Anthropic describes this as loading data "just in time" with tools instead of preloading everything (source).

Notes (or structured note-taking) are facts the agent writes to storage outside the window itself, to be read back at later steps or in later sessions (source). Retrieval answers "find the right page in something large and fixed." Notes answer "remember what happened or what was decided."

def start_session(student_id):
    record = load_json(f"notes/{student_id}.json")   # saved earlier
    return [{"role": "system",
             "content": SYSTEM_PROMPT + "\nStudent notes: " + str(record)}]

def end_session(student_id, new_facts):
    save_json(f"notes/{student_id}.json", new_facts) # survives the session

Summary 1 min

  • The context window is the per-call limit; everything the model uses must be in it.
  • The model keeps nothing between calls; the program re-sends the whole history each step, so cost grows with every step.
  • Nothing survives a session unless the program saves it and reloads it.
  • Retrieval pulls pieces of a large fixed store into context; notes store facts the agent learned.

Say it in your own words: for the makerspace assistant, what goes into context on every call, what is retrieved, and what is saved as notes?
