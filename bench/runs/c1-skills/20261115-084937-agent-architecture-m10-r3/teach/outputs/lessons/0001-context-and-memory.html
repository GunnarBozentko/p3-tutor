The program runs the tool, then sends the result back to the model for its next call. Today's question is what, exactly, that next call contains.

The context window 3 min

A token is a small chunk of text, roughly a short word or word piece, which is the unit a model reads and writes. The context window is the maximum number of tokens the model can take in for one call, its input plus its output. Everything the model knows right now must be inside it: instructions, tool descriptions, the conversation, and tool results. Anthropic's docs describe it as the model's working memory for a request, distinct from the large body of training data (Claude docs: context windows).

The key fact: each model call is independent. The model keeps nothing from the previous call. The program rebuilds the whole input every time, then appends the newest result. Think of a soccer commentator who is handed the full match report before every sentence: the report is the only thing they know.

Two consequences. Cost: you pay for input tokens on every call, so a large tool result is paid for again at each later step. Quality: a bigger context is not automatically better. Anthropic describes context as a finite attention budget: as it fills, recall degrades, so the goal is the smallest set of high-signal tokens (Anthropic: effective context engineering). Research also shows models use information near the start and end of a long input better than information in the middle (Liu et al., "Lost in the Middle").

A common mix-up

"The model remembers the conversation." It is tempting because chat apps feel continuous. In fact the program resends the transcript each time; if it leaves a message out, the model has no trace of it.

Memory between steps and sessions 2 min

Since the model is stateless, all memory in an agent is text that the program stores somewhere and puts back into the context. There are two scopes.

ScopeWhere it livesExample
Between steps (one request)The message list in the program's variablesThe calendar result, still present at step 3
Between sessions (many visits)A file or database outside the model"Sam passed laser cutter training on Oct 3"

When a session ends, the message list is gone. To remember a student's training status, the program must write a note: save a short fact to a file or database, then load it into the context at the start of the next session. Anthropic calls this structured note-taking, and notes the agent can write and re-read let it keep state far beyond one window (Anthropic). When the context nears its limit within one long task, the program can also compact it: summarize the history and continue from the summary.

notes = json.load(open("students.json"))      # saved between sessions
context = [system_prompt, notes[student_id]]  # loaded into this session
# ... loop runs; context grows ...
notes[student_id]["laser_trained"] = True     # write a note
json.dump(notes, open("students.json", "w"))

Retrieval 2 min

Your manuals are far too long to paste into every call. Retrieval means fetching only the few relevant pieces, such as a manual page or section, and adding them to the context for this step. The usual design: split the manuals into chunks ahead of time, then give the model a search_manuals(query) tool that returns the best-matching chunks. Anthropic calls this loading data "just in time" through tools, instead of loading everything up front (Anthropic).

Retrieval is memory with a search step: the full manuals sit outside the context (cheap, unlimited), and only the retrieved chunks enter it (paid for, limited).

Worked example and practice 1.5 min

Worked example

The instructions, tools and question total 2,100 tokens. The model is called 4 times (3 tool calls, then the answer). Each tool result adds r tokens. What is the total input over the request?

  • Call k receives 2,100 + (k−1)·r tokens, because results accumulate.
  • Sum over k = 1..4: 4 × 2,100 + r(0+1+2+3) = 8,400 + 6r.
  • With a 1,500-token retrieved chunk: 8,400 + 9,000 = 17,400 tokens.
  • With a 12,000-token whole chapter: 8,400 + 72,000 = 80,400 tokens, about 4.6 times more.

Summary 0.5 min

  • The context window is everything the model sees in one call; it holds instructions, tools, history and tool results.
  • The model is stateless: the program rebuilds the context at every step, so input cost grows with each step.
  • Memory across steps is the message list; memory across sessions is notes saved outside the model and reloaded.
  • Retrieval keeps large documents outside the context and loads only the relevant chunks.
