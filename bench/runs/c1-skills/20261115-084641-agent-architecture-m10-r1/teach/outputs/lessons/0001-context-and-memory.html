Context and memory in an agent

Why this matters for you

Warm-up 1 min

Recall

In the agent loop, who actually runs a tool: the model or the program around it? And how many model calls does a run with three tool requests make?

Check your answer

The program runs the tool; the model only outputs a request. Three tool requests plus the final answer is four model calls. Each call is separate, which is exactly why context matters below.

The context window 2 min

A model does not remember anything on its own. Each call, it reads one block of text and writes the next tokens (a token is a chunk of text, roughly three-quarters of a word). The context window is that block: everything the model can see in one call, and it has a fixed maximum size measured in tokens (Anthropic, Context windows). The block holds the system prompt, the tool descriptions, the conversation so far, and every tool result.

Analogy: a soccer coach who gets a fresh whiteboard at every substitution. Whatever is not written on the board for this call does not exist for the model.

Bigger is not free or even better. Anthropic's engineering team notes that as the number of tokens grows, the model's ability to recall information accurately from it decreases, which they call context rot, and recommends the smallest set of high-signal tokens that gets the job done (Anthropic, Effective context engineering). Tokens also cost money: you pay for the input on every call.

Between steps and between sessions 2 min

Between steps in one run, the program keeps a list of messages and sends the whole list again on every call, with the newest tool result appended. That list is the only thing carrying state from step to step. The model itself is unchanged, so the context grows each step, and the input you pay for grows with it.

Between sessions, nothing carries over by default. When the student closes the chat, the list is gone; a new session starts with an empty window. Anything the assistant should know next visit, such as "Riley completed laser cutter training", must be written somewhere outside the context and loaded back in.

A common mix-up

"The model learns from our conversations, so it will remember the student next week." It is tempting because chatbots seem to remember within a chat. But that is the message list being resent; the model's weights do not change. Without a saved record that your program loads, a new session knows nothing.

Check yourself

A student finishes laser cutter training on Monday and returns Friday in a new session. What lets the assistant know?

Show the answer

The third: a saved record loaded into the new context. The window is empty at the start of each session and the model does not learn from use.

Retrieval and notes 2 min

Two tools handle what does not fit or does not persist. Retrieval fetches only the relevant pieces of a large source into the context when needed. For the manuals: split each manual into chunks, search them for the student's question (by keyword or by embedding similarity, a numeric measure of closeness in meaning), and put the top few chunks in the window instead of the whole manual. Anthropic describes this "just in time" approach, where the agent keeps lightweight references and loads data with tools at the moment it needs it (Anthropic).

Notes are memory the agent writes outside the window and reads back later. Anthropic's memory tool is a file-based version: Claude checks a memory directory before starting a task, saves what it learns to files, and reads them in later conversations. Your code supplies the storage (Anthropic, Memory tool). For you, a per-student record is a note file or database row that your program loads at session start.

Worked example and practice 2 min

Worked example

The system prompt and tools take 1,000 tokens. Each tool result adds 500 tokens (ignore the model's own output). The run makes 4 model calls. How many input tokens are billed in total?

  1. The window is resent each call, so count each call's input separately.
  2. Call 1: 1,000. Call 2: 1,500. Call 3: 2,000. Call 4: 2,500.
  3. Total: 1,000 + 1,500 + 2,000 + 2,500 = 7,000 tokens, not 1,000 + 3 × 500 = 2,500. Growth compounds because old results are paid for again.
Your turn

A manual is 32,000 tokens. Option A puts the whole manual in the context for each of 4 calls. Option B retrieves 3 chunks of 800 tokens each and includes them in each of the 4 calls. First step: price the manual-related tokens per call. Then compare the totals.

Show a solution

Option A: 32,000 per call × 4 = 128,000 tokens. Option B: 3 × 800 = 2,400 per call × 4 = 9,600 tokens. Retrieval uses about 7.5% of the tokens, and also avoids context rot. The price is that retrieval can miss the right page, so test it on real questions.

Summary 1 min

  • The context window is everything the model sees on one call; the model keeps nothing else.
  • Between steps, your program resends a growing message list; cost grows with it.
  • Between sessions, nothing persists unless your program saves and reloads it.
  • Retrieval brings in relevant pieces of big sources; notes carry facts across sessions.

Say it in your own words: for the makerspace assistant, what goes in the context, what is retrieved, and what is saved as a note?
