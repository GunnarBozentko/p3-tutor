Context and memory in an agent

From lesson 0001.

Where information lives

PlaceLastsUse for
Context windowOne model callInstructions, tool descriptions, history, live results. Paid in tokens on every call.
Message list (program)One sessionMemory between steps. Shrink with compaction or by clearing used tool results.
Notes storeAcross sessionsFew verified facts (training status). Write on verified events, load when needed.
Searchable storePermanentLong manuals. Only top chunks enter the window.

Rules

  • The model keeps nothing between calls; the program re-sends the window.
  • Cost of a request = sum of window sizes over its calls (before caching).
  • Context rot: recall drops as the window fills; aim for the fewest high-signal tokens.
  • Knowledge base under about 200,000 tokens: consider putting it all in the prompt with caching.
  • Retrieval: chunk, embed, search; add BM25 for exact identifiers; merge; optionally rerank.

Sources: Anthropic, context engineering; Anthropic, Contextual Retrieval.
